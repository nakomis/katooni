# Katooni main board (KATOO-1)

The JLCPCB-assembled cable tester: an ESP32-S3-MINI-1-N8, five TCA9555 expanders driving and
sensing every conductor of six test ports, a FUSB302B for e-markers, three INA226s for a Kelvin
resistance check, a 2.0" ST7789 panel on a ZIF connector and a buzzer. Power and USB come in on
the house JST-SH 5-pin connector. The board is generated by code, from the circuit to the gerbers,
with a generator cloned from tinycrypt's `hardware/key-board/`. `DESIGN.md` has the parts and the
circuit.

## Build

```bash
ASDF_PYTHON_VERSION=3.11.15 python -m venv .venv
.venv/bin/pip install -r requirements.txt
mkdir -p freerouting && cp <somewhere>/freerouting-2.5.0.jar freerouting/   # Java via asdf (25)
./fetch_parts.sh                                      # only if a part is added (footprints/ is committed)
.venv/bin/python build.py --route                     # Freerouting's log: /tmp/claude-501/katooni-board-route.log
.venv/bin/python -m pytest
```

`build.py` writes `out/main/`: `katooni-main.kicad_pcb`, `drc.json`, `pins.h`, and, only when KiCad's
DRC has no errors and no unconnected items, `bom.csv`, `cpl.csv`, `katooni-main-gerbers.zip` and
the top and bottom renders. `--allow-drc-errors` writes the board and lists the problems in
`out/main/drc-problems.txt` instead of failing. Without `--route` the board is unrouted (useful for
checking placement).

`fetch_parts.sh` talks to easyeda.com, which answers bursts with 403s (it blocked us for a few
minutes on 19 Oct): it now waits 20 s between parts and is resumable. Every 0402 resistor shares one
footprint and symbol, so only one is fetched.

## Generator changes from tinycrypt's

- **4 layers with a GND plane:** `planes=[("GND", "In1.Cu")]`; In2.Cu is a third signal layer.
  `dsn.write_dsn` and `kicad_pcb.write_board` take the planes and the power-class nets as arguments.
- **Power class clearance 0.15 mm** (was 0.2): the USB-C receptacles' pads are 0.23 mm apart, and
  nothing on the board is above 5 V.
- **Non-plated holes:** EasyEDA exports connectors' plastic locating pegs as unnumbered plated pads
  with no ring; `kicadlib.load_footprint` turns them into `np_thru_hole`, and the router treats them
  as obstacles on every layer.
- **GND is never autorouted** (`board/gnd.py`): a fanout via per SMD GND pad before routing,
  stitching vias after, GND pours on F.Cu and B.Cu over the In1.Cu plane.
- **USB-C B-row escapes** (`gnd.escape_vias_any_order`): the receptacles' B-row pads can only
  leave forward, under the body, and the router always stranded one. Each gets a short track to its
  own via before routing; the greedy placement is retried in up to 400 pad orders until all fit.
  The B-row VBUS/GND pads are left unconnected (the plug joins them to the A-row ones).
- **Placement variants:** Freerouting is deterministic for a given layout but chaotic across
  layouts, so `build.py --variant K` nudges the small resistors and capacitors by up to ±0.3 mm
  (seeded, never into an overlap). `board/katooni_board.py` `VARIANT` records the one that routed
  completely. To search again after a change, run a few at once with separate outputs:
  `for v in 1 2 3 4; do .venv/bin/python build.py --route --variant $v --out v$v & done`.
- **Hand-edited footprints:** the RJ45's second shield pad is `SH2`, the USB-A's second shell pad
  `10b` and the micro-B's other shell pads `0b`–`0d`, so that only one shell pad per connector is on
  the shield line (the metal joins the rest). Re-running `fetch_parts.sh` with those parts missing
  would overwrite the edits; it skips parts it already has.
- **An expected DRC error:** each USB-C receptacle's front shell pegs sit in L-shaped plated slots,
  drawn as two overlapping oval slots (pads 24 and 25). KiCad measures each slot's ring against the
  other's hole and reports 0 mm; `build.py` allow-lists exactly those.

## Pins (for the firmware)

`out/main/pins.h` holds the GPIOs, the I²C addresses and the test-line map (an X macro of line,
expander and pin); `board/katooni_board.py` (`GPIO`, `LINES`) is the source. The GPIO table is in
`DESIGN.md`.

J1 (JST-SH, viewed from the top with its opening facing you, pin 1 on the left): 1 VBUS, 2 D−,
3 D+, 4 CC, 5 GND. Debug pads TP1, top to bottom: **EN, RX, TX, G, 3V3**.
